# Тестирование ассистента «ЛабМентор»

## Как запустить тесты

```bash
pip install -r requirements-dev.txt
playwright install chromium     # нужен только для сквозных тестов в браузере
python -m pytest -v --cov=labmentor --cov-report=term
```

Автотесты не требуют ключей API и доступа в интернет: вместо LLM используется сценарная
модель (`tests/conftest.py`), которая возвращает заранее заданные ответы, в том числе вызовы
инструментов агентами. Внешние сервисы (Whisper, Edge TTS, gTTS, DuckDuckGo, Википедия)
подменяются заглушками. Если Playwright не установлен, браузерные тесты пропускаются.

Автотесты работают на демонстрационных методичках из `tests/data/manuals` (закон Ома, модуль
упругости, RC-цепь), поэтому не зависят от методичек курса. Методички курса из `data/manuals`
проверяют тесты эталонного набора и сценариев `smoke_test.py`: в них сценарная модель отвечает
текстом первого найденного фрагмента со ссылкой на источник.

Работу с настоящей моделью проверяет отдельный скрипт `scripts/smoke_test.py` (см. ниже).

## Проверка ответов настоящей модели

Автотесты проверяют логику программы, но не качество ответов модели. Для этого есть пять
способов, от простого к подробному.

**1. Работает ли все вместе: smoke-тест.**

```bash
python scripts/smoke_test.py               # все сценарии
python scripts/smoke_test.py --no-internet # без поиска в интернете и синтеза речи
```

Скрипт проверяет настройки (ключ API, запущена ли Ollama, загружены ли модели), затем выполняет
11 сценариев по методичкам курса: ответ модели, диспетчер, RAG, агент-аналитик с графиком ВАХ
диода, агент-исследователь, блок-схема, анализ осциллограммы, тренировочная защита, контекстное
окно и резюме, отчет DOCX, синтез и распознавание речи. Результаты сохраняются в
`storage/smoke/smoke_report.md`.

**2. Насколько правильные ответы: оценка на эталонном наборе.**

```bash
python scripts/evaluate.py                  # полная оценка
python scripts/evaluate.py --retrieval-only # только поиск, модель не нужна
```

Эталонный набор `data/eval/golden_set.json` содержит 19 вопросов с ключевыми фактами правильного
ответа: по три на работы 1.1-1.5 и четыре по требованиям кафедры к оформлению отчетов (шрифт и
интервал, таблицы, обозначения на схемах, формулы), 12 запросов с правильным исполнителем для
диспетчера и 3 расчета с допуском. Скрипт считает:

| Метрика | Что означает |
|---|---|
| hit@1, hit@k | нужная методичка найдена первой и среди k фрагментов контекста |
| Точность диспетчера | доля запросов, переданных правильному исполнителю |
| Ключевые факты | доля фактов эталона, которые есть в ответе модели |
| Ссылка на источник | модель указала имя методички, как требует промпт |
| Расчеты в допуске | m = 1,7...1,9 по ВАХ диода, τ = 0,95...1,15 с по таблице, τ = 0,8...1,3 с по осциллограмме |

Ответы модели с отмеченными недостающими фактами сохраняются в `storage/eval/eval_report.md`.
Эталон можно дополнять вопросами по своим методичкам.

Поиск по методичкам курса проверен в среде разработки (без векторного поиска, только BM25):
hit@1 = 19 из 19, hit@4 = 19 из 19. Проверка выявила две ошибки, обе исправлены в `knowledge.py`.
Фильтр по номеру работы понимал только запись «№ 2», поэтому вопрос «Какова цель лабораторной
работы 1.2?» находил методичку работы 1.5. Заголовки методичек обрезались до 120 символов, и у
работы 1.4 из заголовка пропадало «КМОП». На демонстрационных методичках такая проверка раньше
нашла третью ошибку: при k = 1 список рангов BM25 обрезался до трех позиций.

**3. Ручная проверка по ключу ответов.** Демонстрационные данные созданы по известным законам,
поэтому правильные ответы заранее известны:

| Вопрос | Правильный ответ |
|---|---|
| Сопротивление по ВАХ (`ohm_law.csv`) | около 101,5 Ом, в допуске ±5 % от номинала 100 Ом |
| Постоянная времени (`rc_discharge.csv`, осциллограмма) | около 1,05 с при расчетном R · C = 1,0 с |
| Модуль упругости (`young_modulus.xlsx`, d = 10 мм, l0 = 100 мм) | около 2,05 · 10⁵ МПа |
| Коэффициент неидеальности диода (`diode_iv.csv`, φT = 25 мВ) | около 1,80 при заданных m = 1,8 и IS = 2,52 нА |

**4. Голосовой диалог: проверка речи.**

```bash
python scripts/check_speech.py
```

Скрипт скачивает модель Whisper (один раз, с индикатором загрузки), проверяет каждый способ
озвучивания (Edge TTS, Google TTS, системный голос) и показывает причину ошибки, затем озвучивает
фразу «Какова цель лабораторной работы номер один?» и распознает ее обратно.

В среде разработки проверено: запись с микрофона в Chromium приходит на сервер файлом WAV
(16 бит, 44,1 кГц) и читается декодером faster-whisper, фильтр тишины находит в ней речь; без
доступа к huggingface.co приложение показывает понятную ошибку, а ответы озвучивает системный
голос (espeak-ng). Распознавание моделью Whisper нужно проверить на своем компьютере.

Проверка на macOS выявила несовместимость библиотек: faster-whisper передает PyAV параметр
`metadata_errors`, убранный в PyAV 19 (вышел 29.09.2026, ставится с Python 3.12), и чтение
аудио падало с ошибкой `TypeError`. Теперь приложение декодирует аудио само и передает модели
готовые отсчеты 16 кГц; регрессионный тест подменяет PyAV так, как ведет себя версия 19.

Мужской голос раньше пропадал без объяснений: если Edge TTS был недоступен (нет сети, ее закрывает
прокси или сбой сервиса), ответ озвучивал gTTS, у которого есть только женский голос. Теперь без
Edge TTS мужской голос берется из системы (Yuri в macOS, Pavel в Windows, espeak-ng в Linux), а
если мужского системного голоса нет, ответ звучит женским голосом и приложение предупреждает об
этом с подсказкой, как установить мужской голос. Edge TTS получает прокси из настроек системы.

Голос Piper проверен на настоящей библиотеке piper-tts 1.8.0 и модели ru_RU-irina-medium (она
скачана с GitHub, потому что huggingface.co в среде разработки закрыт, и совпадает с файлом на
huggingface.co по контрольной сумме): приложение озвучило фразу без интернета, 4,6 с речи вместе с
загрузкой модели заняли около 2 с. Мужская модель ru_RU-dmitri-medium устроена так же, ее имя, путь
и контрольная сумма сверены с каталогом голосов Piper. Если в папку голосов подложить файл с
другой контрольной суммой, приложение его не использует.

Чтение файлов проверено на воспроизведении жалобы «загруженный файл не всегда читается». До
исправления на вопрос «О чем этот файл?» поиск возвращал фрагменты пяти методичек курса, а
загруженный DOCX не попадал даже в первые четыре; текстовый файл в кодировке Windows-1251 терял всю
кириллицу; в памяти диалога не оставалось отметки о загрузке, а файл без вопроса только добавлялся
в базу знаний без ответа. Теперь первым источником ответа становится загруженный документ, в
следующих вопросах он идет первым, но вопрос с номером работы («работа 1.2») находит свою
методичку. Сквозной тест с SPICE-нетлистом на прежней версии падает: чат не принимал такой файл.

Сквозной тест воспроизведения проверен и на прежней версии интерфейса: там он падает, потому что
после нового вопроса продолжал звучать предыдущий ответ с того места, где он остановился, а новый
ответ мог унаследовать позицию предыдущего. Теперь плеер очищается, как только задан новый вопрос,
и каждое обновление плеера сбрасывает позицию воспроизведения на 0.

**5. Трассировка в LangSmith.** LangChain записывает каждый шаг цепочек и агентов: промпт,
найденные фрагменты, вызовы инструментов, ответ модели, время и число токенов. Достаточно
зарегистрироваться на smith.langchain.com и добавить в `.env`:

```ini
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=ваш_ключ
LANGSMITH_PROJECT=labmentor
```

В среде разработки скрипты 1 и 2 с моделью не запускались: сеть закрыта для api.openai.com,
ollama.com и huggingface.co. Их нужно выполнить на своем компьютере после настройки модели.
